Replit Prompt for SaaS School Management System
Objective: Build a modern, scalable SaaS school management system using React JS and Firebase, designed for rural Ugandan schools, surpassing the functionality and user experience of SchoolPay Uganda (https://schoolpay.co.ug/login). The system must offer a sleek, intuitive UI, offline data entry with periodic syncing, mobile money integration (MTN, Airtel), basic analytics for student performance trends, and robust role-based access control. School directors can create schools (physically or via email), with autogenerated usernames based on school name, role, and a cumulative number. Students must have unique payment codes for fee tracking. Class Teachers can generate personalized PDF reports. Upon login, all users (Admin, Director, Head Teacher, Class Teacher, Subject Teacher, Bursar) see a personalized dashboard displaying their school’s logo and name. Only Admins can view all schools; other users are restricted to their school’s data.
Project Requirements
1. Technology Stack

Frontend: React JS (Create React App, Tailwind CSS for styling, React Router for navigation, Zustand for state management, React Query for data fetching).
Backend: Firebase (Authentication, Firestore for database, Storage for files, Functions for serverless logic).
Offline Support: Use IndexedDB (via Dexie.js) for offline data storage and syncing.
Mobile Money Integration: Integrate MTN and Airtel Mobile Money APIs for fee payments (use mock APIs if unavailable in development).
PDF Generation: Use jsPDF for personalized student reports.
Deployment: Host on Firebase Hosting for scalability.

3. Key Features
School Creation (SaaS Model)

Admin: Create schools via a form (fields: school name, location, contact email, phone, logo upload). Each school is a Firestore collection (schools/{schoolId}).
Director: Request school creation via email or form, pending Admin approval. Upon approval, access their personalized dashboard.
School Entity: Each school has isolated data (students, classes, subjects, etc.) in Firestore, with a logo stored in Firebase Storage (schools/{schoolId}/logo).

Personalized Dashboards

Display school logo (fetched from Firebase Storage) and school name (from Firestore) at the top of each user’s dashboard.
Customize dashboard content by role:
Admin: Global overview of all schools (e.g., total schools, users, students).
Director/Head Teacher: School-wide metrics (e.g., total students, attendance rate, unpaid fees).
Class Teacher: Class-specific metrics (e.g., class size, average marks, attendance).
Subject Teacher: Subject-specific metrics (e.g., subject average marks, student performance).
Bursar: Financial metrics (e.g., fees collected, pending payments by payment code).


Use Tailwind CSS for a modern, card-based layout with Chart.js visualizations (e.g., bar charts for attendance, line charts for marks).

Username Generation

Autogenerate usernames: {schoolName}_{role}_{cumulativeNumber} (e.g., KampalaHigh_Admin_001, KampalaHigh_Bursar_002).
Store in Firestore (users/{userId}) with fields: username, email, role, schoolId.
Ensure uniqueness within each school using a cumulative counter per role.

Student Payment Codes

Assign each student a unique payment code (e.g., KampalaHigh_STU_123456) during creation.
Store in Firestore (schools/{schoolId}/students/{studentId}) with field: paymentCode.
Generate via Firebase Functions (format: {schoolName}_STU_{6-digit-random}).
Display in student profiles and payment screens for mobile money tracking.

Personalized PDF Reports for Class Teachers

Enable Class Teachers to generate personalized PDF reports for each student in their class using jsPDF.
Report content: Student name, payment code, class, marks (by subject), attendance summary, performance trends.
Features:
Filter by term, subject, or date range.
Download individual student PDFs or bulk download for all students in the class.
Professional design with school logo, name, and clear formatting.


Store PDFs temporarily in Firebase Storage, delete after 24 hours.

Offline Data Entry

Use Dexie.js for offline storage of data (students, marks, attendance, payment codes) in IndexedDB.
Implement sync mechanism to push data to Firestore when online.
Provide “Sync Now” button and automatic syncing (every 5 minutes when online).
Notify users of sync status (e.g., “Offline: Data will sync when connected”).

Mobile Money Integration

Integrate MTN and Airtel Mobile Money APIs for fee payments using student payment codes (use mock APIs if unavailable).
Payment screen for parents/students to pay fees, showing status and history linked to payment codes.
Store payment records in Firestore (schools/{schoolId}/payments) with fields: studentId, paymentCode, amount, date, status.
Send confirmation notifications via Firebase Cloud Messaging (FCM).

Basic Analytics

Student performance trends (e.g., average marks per subject, class, term).
Visualizations using Chart.js (e.g., line charts for marks, bar charts for attendance, pie charts for payment status).
Role-based scope:
Admin/Director: School-wide analytics.
Head Teacher: School-wide academic/attendance analytics.
Class Teacher: Class-specific analytics (including payment status).
Subject Teacher: Subject-specific analytics.
Bursar: Financial analytics (e.g., payment completion rates).



Reports

Generate PDF reports (academic, financial, attendance) using jsPDF.
Scope by role (e.g., Class Teacher generates class-specific, personalized student reports; Bursar generates financial reports).
Include payment codes in financial reports.
Allow filtering by date, class, or subject.

5. Firebase Setup

Authentication: Firebase Authentication (Email/Password) for user login.
Firestore Structure:schools/{schoolId}/
  metadata (schoolName, logoUrl, location, email, phone)
  students/{studentId} (includes paymentCode)
  classes/{classId}
  subjects/{subjectId}
  exams/{examId}
  marks/{markId}
  attendance/{attendanceId}
  fees/{feeId}
  payments/{paymentId} (links to paymentCode)
users/{userId} (username, email, role, schoolId)


Security Rules:
Admins access all schools.
Other roles access only their schoolId data.
Teachers access only their assigned classes/subjects.
Bursars access financial data (fees, payments) for their school.


Functions: Use Firebase Functions for:
Generating usernames and payment codes.
Processing mobile money payments.
Triggering notifications.

7. Development Steps

Initialize Project:
Run npx create-react-app school-management-system.
Install dependencies: npm install firebase @tailwindcss/react react-router-dom zustand react-query dexie chart.js jspdf @heroicons/react.


Set Up Firebase:
Create a Firebase project, enable Authentication, Firestore, Storage, and Functions.
Add config to src/firebase/firebaseConfig.js.


Implement Authentication:
Create Login/SignUp components with role selection.
Store user data in Firestore.
Generate usernames and payment codes via Firebase Functions.


Build Role-Based UI:
Create personalized dashboards with school logo and name.
Use React Router for role-based routes.
Implement sidebar with role-based navigation.


Add Core Features:
Implement CRUD for students (with payment codes), classes, subjects, exams, marks, attendance, fees, payments.
Add offline support with Dexie.js.
Integrate mobile money APIs.
Build analytics with Chart.js.
Implement personalized PDF reports for Class Teachers.


Test and Deploy:
Test offline functionality, role-based access, payment codes, PDF reports, and personalized dashboards.
Deploy to Firebase Hosting.
Ensure Firestore security rules restrict access.



8. Additional Considerations

Performance: Optimize for low-bandwidth networks (lazy-load images, minimize API calls).
Scalability: Leverage Firestore scalability and Firebase Hosting CDN.
User Experience: Use glassmorphism, gradients, and animations for a modern look; provide tooltips, loading states, and error messages.
Security: Encrypt sensitive data (payment codes, payments); enforce strict Firestore rules.
